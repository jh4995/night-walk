# 세션 마무리 절차

세션을 닫기 전에 이 넷을 한다. **문서가 썩는 건 형식이 나빠서가 아니라 갱신 트리거가 없어서다** —
이 스킬이 그 트리거다.

> 실제로 한 번 놓친 적이 있다. 하네스 1,000줄이 하루 종일 untracked였고, `docs/STATUS.md`는
> "수정 중"이라고 적힌 채 수정이 끝나 있었다.

---

## 1. 커밋 — 미커밋으로 세션을 끝내지 않는다

```
git status --short --untracked-files=all
```

- **작업 단위로 나눈다.** 문서 정리 / 버그 수정 / 기능 추가를 한 커밋에 섞지 않는다.
- 커밋은 사용자가 한다. **메시지를 제안하되 대신 커밋하지 않는다** (사용자가 명시 지시한 경우 제외).

> untracked 파일은 브랜치를 바꿔도 작업 트리에 남는다. 커밋하지 않으면 브랜치 전략이 깨진다.

### 커밋 메시지 형식 (이 형식을 지킨다)

```
<type>(<scope>): <한국어 한 줄 요약>

- <바꾼 것>: <왜 그렇게 했는지 / 안 그러면 무슨 일이>
- <바꾼 것>: <왜>
...
```

- **제목 1줄 + 본문 불릿 5~6개.** `type`은 `feat` / `fix` / `docs` / `chore` / `test`,
  `scope`는 `android` · `harness` 등(없으면 생략). 제목은 한국어로 쓴다.
- **불릿 하나가 한 줄이다.** 줄바꿈으로 쪼개지 않고, 길어도 한 줄에 담는다.
  불릿 사이에 **빈 줄을 넣지 않는다.**
- **각 불릿이 "무엇을 바꿨다 + 왜"를 함께 담는다.** 무엇이 바뀌었는지만 쓰면 diff와 중복이다.
  판단이 갈렸던 지점(왜 다른 선택지를 버렸는지)이 가장 값진 줄이다.
- 버그 수정이면 **어떻게 발견했는지**를 그 불릿 안에 남긴다
  (예: `— harness-verifier가 거짓 음성으로 찾아냈다`). 같은 계열이 또 나올 때 단서가 된다.
- **`Co-Authored-By` 트레일러를 붙이지 않는다.**
- 산문 단락으로 길게 쓰지 않는다. 15줄 넘어가면 불릿로 압축한다.

**제안할 때는 heredoc으로 낸다** — 사용자가 그대로 붙여넣을 수 있어야 한다.
`git commit -m`에 여러 줄을 넣으면 셸이 깨진다.

```bash
git add <paths>
git commit -F - <<'EOF'
feat(harness): 조명 비교 조건·열 단위 방어선·pull_frames 추가

- baseline_diff의 CONDITION_KEYS에 session.lighting_condition 추가: 저조도는 AE가 노출을 늘려 공급 fps 자체를 바꾸므로, 밝은 방 런과 야간 런을 비교하면 코드가 그대로여도 회귀로 오판정된다
- 중복 열은 경고가 아니라 FrameLogError: DictReader가 마지막 값만 남겨 성한 값이 파괴되는데 이름이 KNOWN_COLUMNS 안에 있어 미지 열 검사로는 안 걸린다 — harness-verifier가 거짓 음성으로 찾아냈다
EOF
```

⚠️ **heredoc은 Git Bash에서 실행해야 한다.** PowerShell은 `<<'EOF'`를 파싱하지 못하므로,
제안할 때 그 사실을 함께 알린다.

## 2. `docs/STATUS.md` + `docs/PROGRESS.md` 갱신

> **두 문서는 역할이 다르다.** `STATUS.md`는 **읽는** 문서(단서·한계·이슈),
> `PROGRESS.md`는 **훑는** 현황판(단계와 🟢/⏸만).
> 🔴 **`PROGRESS.md`에 ms 숫자를 넣지 않는다** — 넣는 순간 측정 한 번에 틀린 문서가 된다.
> 단계가 바뀌었을 때만 손대고, 수치는 소유 문서로 링크한다.

### `docs/STATUS.md`

**짧게 유지한다.** 길어지면 갱신을 안 하게 되고, 낡은 현황은 없느니만 못하다.

| 섹션 | 갱신 기준 |
|---|---|
| 어디까지 왔나 | 이번 세션에 **완료된 것만**. 진행 중은 여기 쓰지 않는다 |
| 다음 한 수 | 아래 3번과 같은 내용 |
| 알려진 이슈 | 이번에 발견했는데 **안 고친 것**. 숨기지 말고 성격(검증 공백/실측 대기/한계/미수정)을 붙인다 |
| 팀에 막혀 있는 것 | 계약 답변이 왔으면 **그 줄을 지운다** |

⚠️ **"진행 중"이라고 쓴 항목이 남아 있으면 그건 갱신을 안 한 것이다.** 세션이 끝났으므로
진행 중인 것은 없다 — 끝났거나, 다음 한 수이거나, 알려진 이슈다.

## 3. 다음 한 수를 한 문장으로

`docs/STATUS.md`에 들어가는 **한 문장**이다. 모호하면 다음 세션이 상황 파악에만 시간을 쓴다.

- ❌ "PoC 계속 진행"
- ✅ "`/feature-kickoff`로 ②저조도 A안 셰이더를 PassthroughRenderer에 얹어 D칸 실측 — GL timer query를 같이 세워 B·I도 노린다"

## 4. 다음 세션에 붙여넣을 블록을 만든다

3번 한 문장은 `STATUS.md`용이고, 이건 **사용자가 다음 세션 첫 메시지로 그대로 붙여넣을 것**이다.
세션 끝에 채팅으로 낸다(파일로 만들지 않는다 — `STATUS.md`와 같은 내용이 두 곳에 생기면 어긋난다).

**한 메시지로 붙여넣게 만든다.** 슬래시 명령 뒤의 텍스트는 그대로 스킬 인자로 전달되므로,
`/feature-kickoff`와 과제를 쪼개지 말고 하나의 코드블록으로 낸다. 과제가 호출과 함께
들어가야 planner에 바로 위임되고, 되묻는 왕복이 없다.

```
/feature-kickoff <과제 한두 줄>

배경:
- <지금 어디까지 됐는지 + 이어받을 산출물의 경로(베이스라인·모듈 등)>
- <이게 먼저인 이유 — 팀을 막고 있다면 그걸 명시>

반드시 지킬 것:
- <이 과제가 건드리는 `☐` 미확정 항목과, 값 없이 갈 수 있는 범위>
- <before로 쓸 baseline 경로와 같은 조건으로 재라는 지시>
- <측정 수단이 없을 수 있는 지점 → 없으면 "미측정"으로 남기라는 지시>
- <성능 보고에 안전 회귀를 함께 내라 / 지금 못 재면 그 사실을 숨기지 마라>

병행 가능(계약 답변 불필요): <다른 사람 답을 안 기다려도 되는 작업>
```

- 코드블록 안은 **평문으로만** 쓴다. 마크다운 표·중첩 코드블록을 넣으면 붙여넣을 때 깨진다.
- **파일 경로와 수치는 구체적으로** 쓴다(`docs/baselines/<파일>.json`, `p50 32.7ms`).
  다음 세션이 그걸 찾느라 시간을 쓰면 이 블록은 실패한 것이다.
- `/feature-kickoff` 단독으로도 동작해야 한다 — 3번 한 문장이 `STATUS.md`에 있으므로
  그것만 넣어도 같은 지점에서 출발한다. 이 블록은 왕복을 줄이는 최적화다.

## 함께 확인할 것 (해당될 때만)

**측정을 했다면**
- 기준으로 쓸 값인가? → `summary.json`을 `docs/baselines/<날짜>_<라벨>.json`으로 승격해 커밋한다.
  모든 실행이 아니라 **버짓표 칸을 채웠거나 · 팀에 보고했거나 · 앞으로 비교 기준이 될 것**만.
  `outputs/`는 git 추적을 안 하므로, 승격하지 않으면 그 숫자는 이 머신에만 남는다.
- 실측이 나왔으면 `FRAME_BUDGET.md`의 해당 칸을 채웠는가?
  **팀 합의 문서 수정이므로 메인 세션에서만 한다** (서브에이전트 아님).

**계약 답변이 왔다면**
- `INTERFACES.md`의 `☐`를 값으로 바꾸고 변경 이력을 남겼는가? (메인 세션에서만)
- 그 값에 막혀 있던 작업이 `STATUS.md`에서 풀렸는가?

**새 문서를 만들었다면**
- 이미 자리가 있는 주제를 **복사한 것은 아닌가?** 새 정보는 새 문서가 아니라
  **소유 문서를 갱신**해서 반영한다. 같은 표가 두 곳에 생기면 반드시 어긋난다.
- `docs/DOCS_MAP.md`의 문서 지도에 추가했는가?

**서브에이전트를 썼다면**
- verifier가 낸 FAIL 중 **안 고친 것**이 `STATUS.md`의 알려진 이슈에 있는가?
- 자체 검증만 하고 끝냈다면 그 사실을 결론에 남겼는가? (독립 검증과 구분해서)
