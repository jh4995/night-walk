# 밤마실 공통 규칙 (Conventions)

이 저장소를 계획·구현·검증할 때 항상 아래를 따른다.

## 0. 이 프로젝트가 뭔가 (한 문단)

야맹증 저시력자의 야간 보행을 돕는 **폰 온디바이스 실시간 AI 시각보조 앱**.
4단계 파이프라인 ①눈부심 억제 → ②저조도 개선 → ③위험 탐지(YOLO) → ④선택적 강조.
목표는 **720p 15FPS 이상**. 4인 해커톤 팀이며, 이 저장소의 주인은 **팀원2 = 모바일 런타임·통합·검증 오너**다.

---

## 1. Source of truth

요구사항의 최우선 근거는 아래 문서다. 코드나 추측이 아니라 여기서 출발한다.

**루트 4개 = 규약 문서.** 각 문서는 소유 주제가 하나씩이며 겹치지 않는다.

| 문서 | 담는 것 (이 주제는 여기서만 본다) |
|---|---|
| `INTERFACES.md` | 4단계 모듈 인터페이스 **계약** (모델 아티팩트 / ①②시그니처 / 녹화 입력) |
| `FRAME_BUDGET.md` | 단계별 ms **예산**과 측정 용어 정의, 예산 초과 시 레버 |
| `KICKOFF_ROLES.md` | 역할·**오너십 경계** (무엇이 내 일이고 무엇이 아닌지) |
| `PIPELINE_STACK.md` | 스택 12개 결정의 **탈락 후보와 상세 근거** |

**`docs/research/` = 리서치 산출물.** 규약이 아니라 현재 판단의 근거다.

| 문서 | 담는 것 |
|---|---|
| `docs/research/RESEARCH_20260728_PIPELINE.md` | **현행 최신 종합.** 지연 예산(§2), ② A/B/C 판정(§7), 미결질문 5개(§10) — 위 4개에 없는 내용 |
| `docs/research/SUBMIT_20260728_PIPELINE.md` | 위 문서의 팀 배포 축약본. **동결 스냅샷** — 갱신은 RESEARCH 쪽만 |

**`docs/archive/` = 역할이 끝난 문서** (`HANDOFF.md`, `STARTUP_PLAN.md`).
배경 확인용으로만 읽고, **여기서 요구사항을 끌어오지 않는다.** 킥오프 이전 상태라
역할표·스택·미결사항이 현재와 어긋난다.

> **숫자 기준 (2026-07-29 통일 완료):** `docs/research/`의 7/28 리서치가 **현재 결정사항**이다.
> `FRAME_BUDGET.md`는 v0.2에서 **단계별 잠정 배정치를 전부 제거**했고(빈칸 ☐),
> 지연 "130~200ms"는 **미측정**으로 철회됐다.
>
> 🚫 **유효한 ms는 프레임당 예산과 p95 관리선 둘뿐이고, 값은 `FRAME_BUDGET.md` §1과
> `lib/targets.py`에만 있다**(§5). **단계별 배정치(A~J 칸)는 폐기됐다** — 어디선가 보더라도
> 인용하지 않는다. 단계 비용은 실측으로만 말한다(§4).

## 2. ⚠️ 팀 합의 문서는 임의로 수정하지 않는다

위 **루트 4개**는 **팀과의 계약이자 합의 기록**이다. 서브에이전트가 조용히 고치면
팀원들이 보고 있는 문서와 어긋나 버린다.

- **수정 금지.** 바꿔야 할 이유를 찾으면 **고치지 말고 보고**한다.
- 예외: 사용자가 명시적으로 그 문서를 수정하라고 지시한 경우.
- 특히 `FRAME_BUDGET.md`의 **실측 칸**은 실제 측정 결과로만 채운다. 추정치로 채우지 않는다.

## 2-1. 🚫 커밋은 사용자가 한다 — 에이전트가 스스로 커밋하지 않는다

**`git commit`을 실행하지 않는다.** 메인 세션이든 서브에이전트든 예외 없다.
사용자가 **그 요청에서 명시적으로 "커밋해라"라고 지시한 경우에만** 한다.

- **다른 지시에서 유추하지 않는다.** "커밋을 먼저 하고 빌드한다" 같은 절차 서술이나
  `git_dirty=false`가 필요하다는 사실은 **커밋 권한이 아니다.** 그건 커밋이 필요한
  *시점*을 알려 줄 뿐이고, 누가 하는지는 바뀌지 않는다.
- 한 번의 커밋 승인은 **그 커밋에만** 적용된다. 다음 커밋에 이어지지 않는다.
- 커밋이 필요한 지점에 오면 **멈추고, 무엇을 왜 커밋해야 하는지 보고**한다.
  커밋 메시지 초안을 함께 내는 것은 좋다 — 실행만 하지 않는다.
- `git push` · `git reset --hard` · `git rebase` · 브랜치 생성/삭제도 같다.
  **작업 트리와 이력을 바꾸는 것은 사용자 손에 남긴다.**
- `git status` · `git diff` · `git log` · `git show` 같은 **읽기는 자유롭게** 한다.
  오히려 커밋 전 보고를 위해 적극적으로 본다.

왜: 측정 스탬프가 커밋에 묶여 있어(§4) 커밋 하나가 그 뒤 모든 숫자의 출처가 된다.
무엇이 언제 어떤 단위로 들어갔는지는 저장소 주인이 정한다.

## 3. 🚫 미확정 계약값을 지어내지 않는다

`INTERFACES.md`에는 아직 상대방 확정을 기다리는 항목이 `☐`로 다수 남아 있다
(모델 입력 해상도, ①②의 실행 위치, 녹화 코덱 등).

- **`☐` 항목의 값을 임의로 정해서 구현하지 않는다.** 그럴듯한 기본값을 넣으면
  나중에 실제 값과 어긋난 채로 코드가 굳는다.
- 필요하면 **제안값임을 코드와 보고서 양쪽에 명시**하고, 확정 필요 항목으로 올린다.
- 확실하지 않으면 값을 만들지 말고 **질문으로 반환**한다.

## 4. 측정 규약 — 스탬프 없는 숫자는 숫자가 아니다

- 모든 성능 측정은 **`lib/run_utils.py`의 `init_run()`을 거친다.**
  실행 시각(`run_ts`) + git commit + dirty 여부가 `run_meta.json`에 함께 남는다.
- `outputs/` 아래 산출물을 **손으로 만들지 않는다.** 반드시 하네스를 통해 생성한다.
- 보고서·문서에 숫자를 인용할 때는 **어느 `run_ts`에서 나온 값인지** 밝힌다.
- 측정하지 못했으면 **"미측정"이라고 쓴다.** 추정치를 실측처럼 제시하지 않는다.

## 5. 성능 목표

🚫 **판정선 숫자를 여기 적지 않는다.** 값은 두 곳에만 산다:

| 어디 | 무엇 |
|---|---|
| `FRAME_BUDGET.md` §1 | 사람이 읽는 source of truth (프레임당 예산 · p95 관리선 · 지속 조건) |
| `lib/targets.py` | 코드가 읽는 단일 출처. 판정 함수와 로그 라벨이 전부 여기서 나온다 |

**셋째 사본을 만들지 않는다.** p95 관리선은 아직 팀 합의 전(🟡 제안값)이라 바뀔 수 있고,
값이 여러 문서에 흩어져 있으면 그때 조용히 어긋난다.

- 스크립트에 임계값을 직접 쓰지 않는다. `lib/targets.py`에서 가져온다.
- 검증할 때는 **`lib/targets.py`와 `FRAME_BUDGET.md` §1을 대조**한다. 세 번째 값을 기준으로 삼지 않는다.
- 평균만 보고 판정하지 않는다. **분포(p50/p95/p99)로 말한다.**
- 첫 30초 숫자는 데모 근거로 쓰지 않는다.

## 6. 성능 회귀와 안전 회귀는 한 세트

성능 튜닝(탐지 주기 늘리기, 입력 해상도 줄이기)은 **위험물 강조 품질을 직접 깎는다.**

> 속도를 개선했다고 보고할 때는 **같은 변경이 위험물 강조를 굶기지 않았음**을 함께 보고한다.
> 한쪽만 있는 보고는 불완전한 보고다.

이건 팀원2가 팀에서 가져온 검증 항목의 실체다 (`KICKOFF_ROLES.md` 결정 3).

## 7. 재사용

이미 있는 것을 다시 만들지 않는다.

- 측정 실행 기록 → `lib/run_utils.py` (`init_run`, `common_argparser`, `dump_run_meta`)
- 콘솔 인코딩 → `ensure_utf8_console()` (Windows cp949에서 한글·`①`·`—` 출력 시 죽는 것 방지)

## 8. 환경

- **Windows 11**, Python 3.13, 셸은 PowerShell 또는 Git Bash.
- 이 저장소는 `uv`를 쓰지 않는다. **`python`을 직접 호출**한다.
- 편집 시 `.claude/hooks/check_syntax.py`가 `.py`를 즉시 구문 검사한다
  (`.kt`는 Gradle이 느려 건너뛴다 — Kotlin 검증은 android-verifier 몫).

## 9. 보고 원칙

- 검사를 통과한 것만 "통과했다"고 말한다. 실행하지 못했으면 **미실행이라고 명시**한다.
- 실패 출력은 요약하지 말고 **원문 그대로** 싣는다.
- 스펙 대비 미구현·보류 항목이 있으면 사유와 함께 반드시 남긴다.
