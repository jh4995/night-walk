## 2. 입력 사양

```
images : float32 [1, 3, 640, 640]   (NCHW)
```

전처리는 **순서까지 그대로** 따라야 한다.

| 단계 | 내용 |
|---|---|
| ① 리사이즈 | **letterbox** — 종횡비 유지 + **회색 114** 패딩으로 640×640 |
| ② 색 순서 | **RGB** (OpenCV 는 BGR 이므로 반드시 변환) |
| ③ 스케일 | `0..255 → 0..1` (**/255**) |
| ④ 정규화 | **없음** — mean/std 정규화를 넣지 말 것 |
| ⑤ 레이아웃 | HWC → **NCHW**, float32 |

⚠️ **letterbox 파라미터(scale, pad_x, pad_y)를 보관해 둘 것.** 5장의 좌표 역변환에 필요하다.

---

## 3. 출력 사양

```
output0 : float32 [1, 7, 8400]
```

- `7` = `cx, cy, w, h` (4) + **클래스 점수 3개**
- `8400` = 앵커 수 (640 기준 80²+40²+20²)
- 좌표는 **640×640 letterbox 좌표계**의 픽셀값이다 (정규화돼 있지 않다)
- **objectness 채널이 없다** — YOLOv8 계열 이후 구조라 클래스 점수가 곧 신뢰도다

| 채널 | 내용 |
|---|---|
| 0 | `cx` (중심 x) |
| 1 | `cy` (중심 y) |
| 2 | `w` (너비) |
| 3 | `h` (높이) |
| 4 | `person` 점수 |
| 5 | `stairs` 점수 |
| **6** | **`bollard` 점수** ← 신규 |

## 4. 🔴 기존 배포판과의 계약 차이

| 항목 | `c4b_loli0` (2026-08-03) | **`c4e_s3_11n`** (이번) |
|---|---|---|
| 클래스 수 | 2 | **3** |
| 출력 shape | `[1, 6, 8400]` | **`[1, 7, 8400]`** |
| 점수 채널 | 4~5 | **4~6** |
| 입력 | `[1,3,640,640]` | **동일** |
| 전처리 | letterbox·RGB·/255 | **동일** |
| NMS | 그래프 밖 | **동일** |
| 정밀도 | FP32 | **동일** |

**앱이 고쳐야 하는 곳은 한 군데다** — 후처리에서 점수 채널 수를 **2 → 3** 으로 늘리고
`argmax` 범위를 넓힌다. 채널 4 이후를 2개로 하드코딩했다면 거기가 전부다.
**전처리·NMS·좌표 역변환은 그대로다.**

⚠️ **`2 bollard` 의 강조 색이 아직 정해지지 않았다.** `scripts/emphasize.py` 의 `PALETTE`
에 `person`(시안)·`stairs`(노랑)만 있어 `bollard` 는 흰색 fallback 으로 그려진다.
**저시력 사용자에게 색 구분은 기능 요건**이므로 앱 적용 전에 정해야 한다.

## 5. 후처리 절차 (앱 구현)

```
1. output0 을 [7, 8400] 으로 보고 전치 → [8400, 7]
2. 각 행에서 채널 4..6 의 최대값 = conf, 그 index = class_id
3. conf < 임계값 인 행을 버린다            ← 운영 임계 6-2 참고
4. (cx,cy,w,h) → (x1,y1,x2,y2) 로 변환
5. 클래스별 NMS (IoU 0.7)
6. letterbox 역변환:
       x = (x - pad_x) / scale
       y = (y - pad_y) / scale
7. 원본 프레임 좌표계에서 렌더
```

⚠️ **6번을 빼먹으면 박스가 어긋난다.** 출력은 640×640 좌표계이고 원본 프레임은 다르다.

## 6. 성능과 그 사정거리

### 6-1. held-out 실측 (NightOwls recording 34 · 학습 미사용 · `person`)

| 지표 | `c4b_loli0` (기존) | **`c4e_s3_11n`** |
|---|---|---|
| mAP50 | 0.684 | **0.710** |
| mAP50-95 | 0.331 | **0.354** |
| recall | 0.609 | **0.635** |
| precision | 0.787 | 0.787 |
| `stairs` 야간 오탐률 (rec 34) | 0.2% | **0.0%** |
| `stairs` 야간 오탐률 (rec 38) | 0.0% | **미측정** |

재현: `uv run python scripts/compare_detect.py --runs c4b_loli0,c4e_s3_11n --skip-fp38`

**개발 val (혼합 도메인 · 참고치)** — `person` mAP50 0.722 / `stairs` 0.988 /
**`bollard` 0.806**(recall 0.739).

### 6-2. 보행 시점 실야간 (자체 촬영 · 라벨 없음)

계단·볼라드·사람이 **없는** 야간 노면 5장 × 밝기 3단 = 15프레임. 나온 박스는 정의상 오탐이다.

| `stairs` 오탐 | conf 0.25 | conf 0.10 |
|---|---|---|
| `c4b_loli0` (기존) | 6박스 | 22박스 |
| **`c4e_s3_11n`** | **5박스** | **9박스** |

야간 볼라드 사진(`_04`, 정답 2개)에서 **세 밝기 전부 2/2 검출**하고 가까운 볼라드의
confidence 가 **0.759 → 0.785 → 0.804** 로 어두워져도 무너지지 않는다.

> **운영 conf 는 0.25 를 권장한다.** 일괄 0.10 하향은 `stairs` 오탐이 크게 늘어 기각됐고,
> 시간축(트래킹·hold)으로 흡수되지도 않는다 — 오히려 오탐이 화면에 **더 오래 붙어 있다.**
> 패키지 metadata 의 `inference.conf 0.35` 는 내보내기 검증용 기본값이다.

### 6-3. ⚠️ 아직 검증되지 않은 것

- **최종 채택 판정이 끝나지 않았다.** 근거가 **seed 1개**이고 실야간 표본은 15프레임·
  야간 볼라드 1장 규모다. 자체 촬영 야간 평가셋(`C5`)에서 판정한다.
- **rec 34 는 차량 대시캠**이다 — 카메라 높이·속도·모션블러가 보행 시점과 다르다.
- **야간 `bollard` 는 라벨이 없어 recall·FP 를 못 쟀다.** 위 수치는 사진 1장의 정성 확인이다.
- **원거리 계단**은 측정된 적이 없다. 학습 데이터의 계단은 화면을 채운 사진이라, 낮은
  야간 오탐률이 "헛보지 않는다"인지 **"거리 장면에선 아예 발화하지 않는다"**인지 구분되지 않는다.

### 6-4. 🔴 탐지 입력은 **원본 프레임**이다

②(저조도 개선)를 탐지 앞단에 붙이면 `stairs` 야간 오탐이 **0.1% → 5.7% (57배)** 가 된다
(`C7`, 2026-08-02 · rec 34 held-out). 횡단보도·차선 텍스처를 계단으로 오인하는 것이라
**저시력 보행자가 반드시 지나는 곳에서 헛보게 된다.**

```
카메라 ─┬─→ [탐지 경로] 원본 그대로 ──────→ ③ 이 모델 ─┐
        │                                              ↓
        └─→ [표시 경로] ①② 개선 ─────→ ④ 선택적 강조 → 화면
```

**화면에 보이는 영상(②)과 모델에 넣는 영상(원본)이 다르다.** 구조를 그렇게 짜야 한다.
