# 파트 1 — 사용자 테스트용 UI (bbox 색 채우기 + ②③④ on/off 버튼)

> **작성:** 2026-08-28 밤 (팀원2) · **상태:** 착수 전. 결정 완료, 구현 0.
> **소유 주제:** ④가 **어떻게 보이는가**(fill) · 사용자 테스트용 **화면 조작**(on/off).
> **여기서 다루지 않음:** 무엇을 그릴지(→ 파트 2 FSM) · ② 알고리즘 · 모델.

---

## 0. 한 문장

**bbox 안을 클래스 색으로 옅게 채우고, arm 36개 스피너 대신 on/off 버튼 하나로 사용자
테스트를 돌 수 있게 만든다.** 두 가지 다 팀장 지시이고 판정 기준이 이미 정해져 있다.

- 트리 깨끗. ④ FSM은 **진입 4중2 / 해제 1**로 배선돼 폰에 설치돼 있다.

  §5의 야간 세션에서 `entry4of2`를 승격하면 맞춰진다.

## 3. 지금 무엇이 있고 무엇이 없나

**④ 오버레이(`HighlightOverlay.kt`, 575줄)** — **얇은 사각형 스트로크 quad 1패스**
(`GL_TRIANGLES`). 본선 + 그보다 넓은 **검정 밑선**으로 대비를 만든다. 두께는 처리 해상도
짧은 변 기준 720p에서 4px.

🔴 **fill은 이 설계의 전제를 바꾼다.** 파일이 스스로 *"스트로크 quad로 그리면 채워지는
픽셀이 실제 테두리 면적뿐이다"*라고 적어 둔 최적화가 있고, fill은 **박스 면적만큼** 프래그
먼트를 칠한다. 지금 I칸은 "+0.562ms(박스 4개)"이고 08-26 S3에서 **박스 개수와 무관**하다는
결론까지 나왔는데, **fill이 그 결론을 깬다** — 개수가 아니라 **면적**이 설명 변수가 된다.

**UI(`MainActivity.kt` · `activity_main.xml` 105줄)** — arm 스피너 · 조명 스피너 ·
측정 시작/정지 버튼 · HUD 접기 버튼. 레이아웃은 이 파일 하나뿐이다. **사용자용 화면은
처음 만드는 것이다.**

**색 상수(`OverlayClassColors.kt`)** — stairs `(1,1,0)` · person `(1,0,0)` · bollard `(0,1,0)`.
person 빨강은 **상류 명세 이탈로 기록**돼 있고(`PERSON_COLOR_DEVIATION`) 사유가
`session.json` 두 자리로 나간다. **건드리지 않는다.**

## 6. 🔴 어기면 안 되는 제약

1. **fill 알파는 고정값이다.** 🔴 **시간에 따라 알파를 바꾸면 규약 위반이다** —
   `OVERLAY_NO_FLICKER_DESIGN`이 *"점멸·펄스·**알파 변조**가 코드에 없다"*를 선언하고
   있고 광과민 사용자 안전 이슈다. 페이드인/아웃도 금지다.
2. **알파값은 `INTERFACES.md`에 항목 자체가 없다**(계약의 `☐`가 아니라 **항목 부재**).
   평활 계수·FSM 상수와 **같은 틀**을 쓴다 — `_MEASUREMENT_VALUE` 이름 + 근거 문자열 +
   `session.json` 배관. 🔴 **여러 곳에 숫자를 적지 않는다**(반복해 바꿀 값이다).
3. **프레임당 할당 0 · GL 스레드 전용** — 오버레이 경로의 기존 규약이다.
4. **색 상수를 건드리지 않는다** — person 빨강은 이탈로 기록된 값이고 사유가
   `session.json`으로 나간다.
5. **기존 arm 스피너를 없애지 않는다** — 측정 하네스가 36개 arm을 계속 쓴다.
6. **🚫 커밋하지 않는다** — 사용자가 한다.
7. **팀 합의 문서 수정 금지** — `INTERFACES.md`·`FRAME_BUDGET.md`·`KICKOFF_ROLES.md`·
   `PIPELINE_STACK.md`.
8. **측정하지 못했으면 "미측정"이라고 쓴다.** fill을 넣고 I칸을 안 쟀으면 안 잰 것이다.
