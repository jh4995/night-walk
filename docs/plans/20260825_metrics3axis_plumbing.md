## 3. 🔴 3축은 `같은 프레임의 before/after 쌍`을 요구한다

`measure(arm, samples)`가 `arm`을 **호출 가능 객체**로 받아 안에서 `out_img = arm(src)`를 만든다
(`metrics.py:259`, `:294`). 그리고 **마스크를 전부 입력에서 고정**한다:

```python
lamp = L >= lamp_min          # 글레어: 입력에서 광원을 고르고
core_a.append(median(O[lamp])) #         출력의 같은 화소를 본다
dark = dark_mask(L)            # 대비:  입력 기준 암부
cg, g_ref = contrast_gain(L, O, dark)
flat = flat_dark_mask(L)       # 노이즈: "입력 기준 고정 — 모든 arm이 같은 화소를 본다"
sl_b, sc_b = noise_absolute(src,     flat)
sl_a, sc_a = noise_absolute(out_img, flat)
```

이것은 우연이 아니라 **재설계의 뿌리**다. 모듈 머리말이 못 박는다:

> *(a) 측정 대상을 **입력에서 고정**하고 출력에서 같은 화소를 본다
> (재선택하면 '무엇이 어디로 갔는가'를 못 읽는다)*

`flat_dark_mask` 주석은 재선택했을 때의 구체적 역전까지 적는다 — *"노이즈를 키운 arm일수록
'평활' 판정 영역이 좁아지고 더 조용한 곳만 남아, **노이즈를 키울수록 좋게 나오는** 역전이 생긴다."*

**→ `after` 한 장만으로는 3축 중 하나도 계산되지 않는다.**

> 🟢 **API 자체는 걸림돌이 아니다.** 쌍만 있으면 `arm`을 조회 함수로 만들어 파일 쌍을 넣을 수 있다.
> 막는 것은 API가 아니라 **쌍의 부재**다.

## 4. 프레임 확보 경로 — 실측으로 확인한 것

### 4-1. `adb exec-out screencap` — 화면은 담기지만 규격을 못 맞춘다

**실측 (2026-08-25, SM-A346N, 앱 변경 0줄, 측정 미시작):**

| 확인 항목 | 결과 |
|---|---|
| GLSurfaceView 출력이 담기는가 | 🟢 **담긴다.** 검은 화면 아님 — 카메라 영상이 그대로 나온다 |
| 정보 패널 가림 | 🟢 **`정보 숨기기` 버튼으로 접힌다.** 접으면 상단이 완전히 깨끗하다 |
| 접어도 남는 것 | 하단 버튼 바 + 시스템 내비 바 (원본 좌표 y ≳ 1977) → **위쪽 1080×1970을 크롭해 쓴다** |
| 측정 런이 생기는가 | 🟢 **안 생긴다.** `측정 시작`을 누르지 않으면 기기에 런 디렉토리가 만들어지지 않는다 |
| PNG 형식 | 1080×2340, 8bit, colortype 6 (RGBA) |
| 🔴 해상도·스케일 | **1280×720 → 1080×2340으로 늘어난 픽셀이다** |

**늘어나는 메커니즘 (앱 코드 확인):** 레이아웃의 `GLSurfaceView`가 `match_parent`/`match_parent`
전체화면이고(`android/app/src/main/res/layout/activity_main.xml:8-11`), 파이프라인은 720p FBO에
그린 뒤 마지막 present 패스에서 기본 프레임버퍼에 `glViewport(0, 0, surfaceWidth, surfaceHeight)`로
**화면 크기 전체에 blit**한다(`android/app/src/main/java/com/bammasil/poc/gl/PassthroughRenderer.kt:1010`
외 3곳). 즉 screencap이 담는 것은 **GPU 스케일러를 통과한 뒤**의 픽셀이고, 720×1280 → 1080×2340이라
가로세로 배율도 서로 다르다(약 1.5× / 1.83×).

**이것이 3축에 주는 피해 (축마다 다르다):**

| 축 | 피해 | 이유 |
|---|---|---|
| **노이즈** | 🔴 **가장 심하다. 계통적으로 과소** | Immerkaer는 화소 단위 요동을 재는데 업스케일 필터가 정확히 그것을 저역통과시킨다. 상류 자신이 *"노이즈는 스케일에 민감"* 이라고 적었다 |
| **대비** | 🔴 **다른 공간주파수를 잰다** | `local_std(k=9)`가 1.5~1.83× 늘어난 화면에서는 원본 기준 ~5×5 이웃이 된다 |
| **글레어 코어** | 🟡 셋 중 가장 견디지만 안전하지 않다 | 화소별 절대 임계(≥235)라 리샘플에는 비교적 둔하지만, 디스플레이 경로가 톤·감마를 건드리면 마스크가 이동한다 |

> **결론: screencap은 3축 채점의 입력이 될 수 없다.** §3의 쌍 부재와 §4-1의 리샘플이
> **각각 독립적으로** 자격을 무너뜨린다. 둘 중 하나만 고쳐도 부족하다.

### 4-2. 근사 경로 (삼각대 + 정지 장면 2런) — 권하지 않는다

`passthrough` 런과 ② 런을 따로 찍어 쌍으로 취급하는 길. **앱 변경은 0이지만 근사가 이중이다** —
같은 프레임이 아니고(장면·노출·AE/AWB가 그 사이 움직인다), 픽셀은 여전히 늘어나 있다.
**노이즈·대비 축은 이 경로로 읽지 않는다.** 굳이 쓴다면 글레어 코어 하나뿐이고,
그때도 "근사이며 규격이 아니다"를 숫자 옆에 붙인다.

### 4-3. 🟢 이미 있는 것 — `parity/` 덤프의 `sample_NN_src.yuv`

탐지 이식 대조용 덤프가 **카메라 원본 YUV를 1280×720 네이티브로** 이미 저장한다
(`docs/plans/20260806_detect_parity_dump_format.md`). 이것은 진짜 `before`다 — 리샘플 없음.

🔴 **다만 짝이 되는 `after`가 없다.** 덤프는 **탐지 경로**에서 뜨는데 ②는 설계상 탐지 앞단에
붙지 않는다(경로 분리 — 모델 계약이 그렇게 요구했다). 그래서 이 덤프에는 ②를 통과한 같은
프레임이 존재하지 않는다.

## 5. 🟢 지금 할 수 있는 것 — 기준 기대값 만들기 (앱 변경 0, 근사 0)

상류 `lowlight.py`의 arm 등록부에 **`D1A1`과 `D1A1+bf`가 그대로 있다**(`lowlight.py:472-473`) —
우리가 이식한 `drago_clahe_chain` / `drago_clahe_chain_bf`와 같은 조합이다.

그러므로:

```
parity/ 덤프의 sample_NN_src.yuv  (우리 장면, 네이티브 1280×720)
        → BGR 변환
        → 상류 lowlight.build("D1A1")  (레퍼런스 구현)
        → metrics.measure(arm, samples)
```

**이것이 답하는 것:** *"우리가 실제로 찍는 장면에서 3축이 어느 대역에 놓이는가"* —
즉 **우리 이식이 맞혀야 할 목표 숫자**. 상류의 LOL·자체 촬영 표본이 아니라 **우리 카메라·우리
장면**에서 나온 값이다.

**이것이 답하지 못하는 것:** 🔴 **우리 이식의 품질.** 여기서 도는 것은 상류 구현이지 우리 셰이더가
아니다. 우리 이식이 상류보다 계통적으로 밝다는 측정(23.5~55.6 LSB)이 있으므로 **두 숫자를
같은 것으로 읽으면 안 된다.**

⚠️ 실행에 `numpy` + `opencv-python`이 필요하다. 이 저장소에서 stdlib 밖을 쓰는 것은
`detect_parity.py`(numpy·onnxruntime)뿐이고 **cv2는 처음**이다. 상류 코드를 우리 트리에 복사하지
말고 클론에서 돌린다(라이선스·출처 혼동 방지).

## 6. ⚠️ 골든 이미지(§B-6)는 여전히 필요하다 — 취소되지 않았다

3축과 골든 이미지는 **재는 대상이 다르다.**

| | 재는 것 | 답하는 질문 |
|---|---|---|
| **3축** | 결과가 좋은가 | "이 arm이 야간 시인성을 개선하는가" |
| **골든 이미지** | 이식이 원본과 같은가 | "우리 셰이더가 상류 구현과 같은 픽셀을 내는가" |

**우리 이식이 상류보다 계통적으로 밝다는 측정(23.5~55.6 LSB)이 있는 한 후자가 필요하다.**
§5의 경로는 상류 구현을 돌리는 것이라 이식 차이를 **정의상 못 본다.**
🚫 **§B-6 요청을 취소된 것으로 적지 않는다.**
