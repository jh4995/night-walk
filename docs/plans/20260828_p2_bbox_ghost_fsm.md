# 파트 2 — bbox 잔상 제거 (C+B FSM)

> **작성:** 2026-08-28 (팀원2) · **상태:** 착수 전. 설계 결정 완료, 구현 0.
> **소유 주제:** ④ 오버레이가 **무엇을 그릴지** 정하는 규칙 — 진입·해제 조건, TTL 단위.
> **여기서 다루지 않음:** fill·on/off 버튼(→ 파트 1) · INT8 arm 추가 · ② 알고리즘.

## 0. 한 문장

**박스가 물체보다 0.6초 늦게 사라지는 잔상을, hold TTL 을 프레임 단위에서 게시 단위로
바꾸고 진입·해제를 FSM 으로 나누어 없앤다.** 잔상↔깜빡임이 맞바꿈 관계이므로 잔상만
줄이면 실패이고, `overlay.flicker` 회귀를 함께 낸다.

## 1. 착수 시점의 저장소 상태 — 배선은 이미 커밋됐다

직전 세션에서 **③ 탐지 모델을 INT8 로 배선**했고 `0f2bce0` 으로 커밋됐다(8파일).

|---|---|
| `android/app/build.gradle.kts` | `detectModelDir` → `models/0826/…-INT8`, `detectMetadataFileName` 변수 신설 |
| `android/app/src/main/java/…/detect/DetectContract.kt` | `declaredSource` KDoc 정정 (파일명 가정 제거) |

- 🔴 **측정 시점에는 `GIT_DIRTY=false` 여야 한다** — 구현 중에는 dirty 여도 되지만,
  깜빡임 회귀 판정(2-6) 같은 **정식 측정은 커밋 뒤에** 돈다.
- 🚫 **커밋은 사용자가 한다.**

## 2. 결정된 것 — 재논의하지 않는다

사용자가 선택지를 보고 고른 결과다.

| 항목 | 값 |
|---|---|
| 방식 | **C(진입) + B(해제) 조합** = 팀장이 말한 FSM |
| **진입** | 최근 **3게시 중 2회** 탐지되면 `ACTIVE` (그리기 시작) |
| **해제** | **연속 1회 미탐지**면 즉시 제거 |
| TTL 단위 | 프레임 → **게시(publish) 단위**로 전환 |
| 페이드아웃 | 🚫 **금지** — 알파 변조는 깜빡임 규약 위반 |

위 진입·해제 수치는 **시작값**이다. 야간 실측 뒤 조이거나 풀 수 있다.

## 3. 왜 이 설계인가 — 재도출이 비싸다

**(1) 잔상의 직접 원인은 hold 다.**
`OVERLAY_HOLD_FRAMES_MEASUREMENT_VALUE = 18` 프레임 ≈ **0.6초**
(`RenderArm.kt:2001`). 탐지가 끊겨도 박스가 0.6초 더 남는다 — 이것이 사용자가 말한 "잔상".

**(2) IIR 은 주범이 아니다.**
`OVERLAY_IIR_ALPHA_MEASUREMENT_VALUE = 0.35` (`RenderArm.kt:2014`), 30FPS 에서 95% 수렴이
**약 0.23초**다. 사용자 보고의 "2초"를 설명하지 못한다. ⚠️ 2초의 분해는 **미측정**이다.

**(3) 프레임 단위로는 0.33초가 한계다.**
탐지 게시 주기가 약 9프레임(3.4Hz / 30FPS)이므로 **hold 를 9 밑으로 내리면 정상 탐지
중에도 만료되어 깜빡인다.** 그래서 프레임 단위 조정으로는 0.6초 → 0.33초까지밖에 못 간다.

**(4) 게시 단위로 세면 공짜 이득이 있다.**
탐지가 빨라지면 잔상이 **자동으로** 줄어든다. INT8 로 게시 주기가 2배 빨라지면
해제 k=1 기준 0.29초 → 0.15초. 프레임 단위는 그대로 0.33초다.

**(5) 잔상↔깜빡임은 맞바꿈이다.**
hold 를 그냥 줄이면 깜빡임이 는다. 깜빡임은 상류가 **광과민 사용자의 안전 이슈**로
규정했다. FSM 은 "확인된 트랙만 그린다"이므로 **hold 를 줄여도 깜빡임이 늘지 않는** 유일한
구조다 — 이것이 팀장 지시(FSM)와 잔상 목표가 만나는 지점이다.

## 4. 이미 확보한 값 — 다시 조사하지 않는다

| 값 | 출처 |

| I칸 = +0.562ms (박스 4개) | 🔴 **박스 개수 없이 인용 금지** |

## 6. 🔴 어기면 안 되는 제약

1. **프레임당 할당 0** — `OverlaySmoother` 는 배열을 생성 시 한 번 잡고 in-place 로
   재기록한다. GL 스레드에서 GC 가 돌면 그것이 곧 프레임타임 꼬리다. 히스토리 버퍼도
   고정 배열로 잡는다.
2. **점멸·펄스·알파 변조 없음** — `OVERLAY_NO_FLICKER_DESIGN`. 페이드아웃으로 잔상을
   부드럽게 지우고 싶어지지만 **금지**다.
3. **GL 스레드 전용** — `OverlaySmoother` 는 전부 GL 스레드에서만 부른다.
4. **정책값은 `INTERFACES.md` 에 항목 자체가 없다**(계약의 `☐` 가 아니라 항목 부재).
   기존 `OVERLAY_SMOOTHING_PROVENANCE` 와 같은 방식으로 상수 + 근거 문자열을 두고
   `session.json` 으로 낸다.
5. **성능과 안전을 함께 낸다**(규칙 6) — 잔상을 줄였으면 깜빡임이 늘지 않았음을 같이
   보인다. 한쪽만 있는 보고는 불완전하다.
6. **🚫 커밋하지 않는다** — 사용자가 한다.
7. **팀 합의 문서 수정 금지** — `INTERFACES.md`·`FRAME_BUDGET.md`·`KICKOFF_ROLES.md`·
   `PIPELINE_STACK.md`. 고칠 이유를 찾으면 보고한다.
