# 기준 측정값 (baselines)

`outputs/`는 git이 추적하지 않는다. 그래서 **승격하지 않은 숫자는 그 머신에만 남는다** —
노트북이 바뀌거나 팀원이 확인하려 하면 근거가 없다.

여기엔 **기준이 된 측정만** 올린다. 그러면 `baseline_diff.py`가 세션·기기를 넘어서 동작한다.

## 승격 기준 (셋 중 하나면)

- `FRAME_BUDGET.md`의 칸을 채운 측정
- 팀에 숫자로 보고한 측정
- 앞으로 비교 기준으로 쓸 측정

나머지 수십 개 런은 `outputs/`에 두고 승격하지 않는다.

## 방법

```bash
cp outputs/poc_baseline/<run_ts>/summary.json docs/baselines/<날짜>_<라벨>.json
```

`summary.json`을 **그대로** 복사한다. 수 KB이고, git commit·기기 메타·판정·경고가 이미 안에 있다.
**손으로 만들거나 편집하지 않는다** — 하네스를 거치지 않은 숫자는 스탬프가 없어 비교 불가다.

명명: `<YYYYMMDD>_<무엇을_잰_것인지>.json` — 예 `20260731_poc_empty_a34.json`

## 비교

```bash
python scripts/baseline_diff.py \
  --baseline docs/baselines/20260731_poc_empty_a34.json \
  --current  outputs/poc_baseline/<run_ts>/summary.json
```

⚠️ **조건이 다르면 비교가 아니라 착시다.** 같은 기기·같은 빌드 타입·같은 파이프라인 구성이어야
한다. `baseline_diff.py`가 `CONDITION_KEYS`로 검사해 다르면 경고를 먼저 낸다.

## 지금 여기 있는 것

| 파일 | 무엇 | 조건 |
|---|---|---|
| `20260730_poc_empty_a34.json` | **빈 파이프라인 PoC 베이스라인** (런A) | A34 / release / `pipeline_stages: []` / `indoor_bright` / 분석 창 **642.5s** |
| `20260730_poc_empty_a34_repeat.json` | 같은 조건 반복 런B — **런 간 노이즈의 근거** | 위와 동일 / 분석 창 **648.2s** |

> 지속시간은 `t_recv_ns`의 **실제 span**이다(warmup 30초 제외 후). 세션 전체는 672.5s · 678.2s.
> `p50 × 표본수`로 유도하면 628.7s · 633.5s가 나오는데 **그건 다른 값이다** — 처음 이 표에
> 그 유도값을 적었고 독립 검증에서 잡혔다.

**런A↔런B 실측 노이즈: p50 −0.12% / p95 +0.47% / p99 +1.10% / mean 0.00%.**
`baseline_diff.py`의 `DEFAULT_NOISE_PCT = 5.0`은 이 조건에서 **넉넉한 값**이다 — 5% 미만의 진짜
회귀는 놓친다. 다만 이 노이즈는 **처리가 없어서 분산이 작은** 것이므로, ①②③④가 붙은 뒤 다시 재고
그때 임계를 조정한다. 지금 좁히지 않는다.

> ⚠️ **두 런의 스탬프는 `git_dirty: true`다** (당시 하네스 변경과 `android/`가 미커밋).
> 측정 직후 같은 트리를 커밋했으므로 코드 내용은 git에 보존돼 있으나, `summary.json`이 가리키는
> 커밋(`a23abe4`)은 그 **직전** 상태다. 정확한 재현이 필요하면 커밋 이후로 재측정해야 한다.

### 이 숫자로 말할 수 없는 것

- **야간 성능** — 라벨이 `indoor_bright`다. 저조도에서는 AE가 노출을 늘려 공급 fps 자체가 떨어지므로
  `outdoor_night_*` 런을 따로 재야 한다.
- **①②③④가 붙은 프레임타임** — 이 값은 카메라 공급에 묶인 **바닥값**이다.
- **안전 회귀** — 탐지 미구현으로 `evaluated: false`다.
- **B·I·J 칸** — 처리·오버레이가 없어 잴 대상이 없다. `FRAME_BUDGET.md` §6 배정과 어긋난 상태다.

> 그 숫자를 팀에 공유할 때는 단서를 반드시 붙인다 — 처리가 없는 파이프라인의 프레임 간격은
> **연산 비용이 아니라 카메라 공급 속도**다. 여유의 상한이 아니라 **바닥값**이고,
> 여기서부터 ①②③④ 비용이 더해진다.
