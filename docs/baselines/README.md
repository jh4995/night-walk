# 기준 측정값 (baselines)

`outputs/`는 git이 추적하지 않는다. 그래서 **승격하지 않은 숫자는 그 머신에만 남는다** —
노트북이 바뀌거나 팀원이 확인하려 하면 근거가 없다.

여기엔 **기준이 된 측정만** 올린다. 그러면 `baseline_diff.py`가 세션·기기를 넘어서 동작한다.

## 승격 기준 (셋 중 하나면)

- `FRAME_BUDGET.md`의 칸을 채운 측정
- 팀에 숫자로 보고한 측정
- 앞으로 비교 기준으로 쓸 측정

나머지 수십 개 런은 `outputs/`에 두고 승격하지 않는다.

## 방법

```bash
cp outputs/poc_baseline/<run_ts>/summary.json docs/baselines/<날짜>_<라벨>.json
```

`summary.json`을 **그대로** 복사한다. 수 KB이고, git commit·기기 메타·판정·경고가 이미 안에 있다.
**손으로 만들거나 편집하지 않는다** — 하네스를 거치지 않은 숫자는 스탬프가 없어 비교 불가다.

명명: `<YYYYMMDD>_<무엇을_잰_것인지>.json` — 예 `20260731_poc_empty_a34.json`

## 비교

```bash
python scripts/baseline_diff.py \
  --baseline docs/baselines/20260731_poc_empty_a34.json \
  --current  outputs/poc_baseline/<run_ts>/summary.json
```

⚠️ **조건이 다르면 비교가 아니라 착시다.** 같은 기기·같은 빌드 타입·같은 파이프라인 구성이어야
한다. `baseline_diff.py`가 `CONDITION_KEYS`로 검사해 다르면 경고를 먼저 낸다.

## 야간 3건이 말하는 것 (2026-07-31 실측)

**1. 저조도에서 공급 주기가 벌어진다는 가정은 이 기기에서 성립하지 않는다.**

| | 실내(7/30) | night_lit | night_dark | night_dark+drago |
|---|---|---|---|---|
| `recv_interval_ms` p50 | 32.46 | 32.77 | 32.61 | 32.60 |
| 프레임타임 p50 / p95 | 32.70 / 38.07 | 32.86 / 38.81 | 32.77 / 39.05 | 32.92 / 39.00 |

어둠 속에서도 카메라가 30fps를 그대로 준다. **실내에서 잰 숫자가 야간에도 대체로 통한다** —
위 "말할 수 없는 것" 항목의 야간 성능 경고를 이 세 건이 부분적으로 해소한다.

**2. 🔴 그런데 지연이 야간에 +13ms 나빠졌다.**

`capture_to_render_ms` p50: 실내 **78.8** → night_lit **91.3** / night_dark **91.5** / drago **93.5**.
공급 주기는 같은데 취득~제출이 늘었다 — ISP가 프레임을 더 오래 붙든다.
`FRAME_BUDGET.md` §2가 이미 "처리 0인데 하한이 프레임당 예산을 넘는다"를 🔴로 띄웠는데,
**실제 사용 조건에서 더 나빠졌다.** 그리고 이 값에는 **GPU 실행 시간이 안 들어 있다.**

**3. 11분 연속 GPU 부하에서 발열 드리프트가 없다.**

드리프트가 0.04ms 수준이고 tail은 오히려 좁아진다. 7/30 측정이 "처리가 없어 스로틀링할 부하가

🔴 **암부 관찰은 상류 실측과 어긋난다.** 상류(`lowlight_classical.md` 6-3)는 D1의 암부 증폭을
*"StairNet 야간에서 대비배율 1.01x — 거의 아무것도 드러내지 못했다"* 로 쟀다. 우리가 D1을 고른
이유는 암부가 아니라 **강광원 억제**(상위 1% −81, 포화 1/17)였다.

어긋남의 유력한 원인은 **우리 이식의 상류 이탈 3건**이다 — 독립 검증이 우리 이식을
OpenCV 대비 **계통적으로 더 밝다**고 쟀다(실기기 프레임 23.5 LSB, 합성 야간+강광원 55.6 LSB).
즉 **"더 잘 보인다"의 상당 부분이 진짜 Drago가 아니라 이탈일 수 있다.**
→ `RenderArm.DRAGO_DEVIATION` · `RESEARCH_20260731_UPSTREAM.md` §3.
**§B-6 골든 이미지가 있어야 "좋아 보인다"와 "상류와 같다"를 구분할 수 있다.**

플리커가 없었던 것은 팬이 **연속** 변화라 전역 통계가 프레임마다 조금씩만 바뀌기 때문으로 보인다.
**안 해본 전환이 있다** — 헤드라이트처럼 강광원이 **갑자기** 프레임에 들어오는 경우.
그건 `Lmax`를 불연속으로 바꾸고 Drago의 톤커브가 거기 직접 걸려 있어, 화면 전체가 한 번에
어두워졌다 돌아올 수 있다. **미관측이다.**

> 여기서부터 ①②③④ 비용이 더해진다.
