# 기준 측정값 (baselines)

`outputs/`는 git이 추적하지 않는다. 그래서 **승격하지 않은 숫자는 그 머신에만 남는다** —
노트북이 바뀌거나 팀원이 확인하려 하면 근거가 없다.

여기엔 **기준이 된 측정만** 올린다. 그러면 `baseline_diff.py`가 세션·기기를 넘어서 동작한다.

## 승격 기준 (셋 중 하나면)

- `FRAME_BUDGET.md`의 칸을 채운 측정
- 팀에 숫자로 보고한 측정
- 앞으로 비교 기준으로 쓸 측정

나머지 수십 개 런은 `outputs/`에 두고 승격하지 않는다.

## 방법

```bash
cp outputs/poc_baseline/<run_ts>/summary.json docs/baselines/<날짜>_<라벨>.json
```

`summary.json`을 **그대로** 복사한다. 수 KB이고, git commit·기기 메타·판정·경고가 이미 안에 있다.
**손으로 만들거나 편집하지 않는다** — 하네스를 거치지 않은 숫자는 스탬프가 없어 비교 불가다.

명명: `<YYYYMMDD>_<무엇을_잰_것인지>.json` — 예 `20260731_poc_empty_a34.json`

## 비교

```bash
python scripts/baseline_diff.py \
  --baseline docs/baselines/20260731_poc_empty_a34.json \
  --current  outputs/poc_baseline/<run_ts>/summary.json
```

⚠️ **조건이 다르면 비교가 아니라 착시다.** 같은 기기·같은 빌드 타입·같은 파이프라인 구성이어야
한다. `baseline_diff.py`가 `CONDITION_KEYS`로 검사해 다르면 경고를 먼저 낸다.

읽는 사람이 반대 결론을 낸다.** D칸은 `gpu_sum` 차분 쪽이다(`FRAME_BUDGET.md` §3 주3).

**3. ⚠️ "CLAHE가 비싸다"는 오독이다.** clahe의 **알고리즘 고유부(analyze+build 1.867)가 셋 중
가장 싸다.** 총량에서 뒤지는 원인은 `apply`(3.461)이고, 그 대부분은 A1·A2가 **공유하는
LAB 변환**(pow ×9)이다. 경량화 레버는 통계 쪽이 아니라 색공간 변환 쪽에 있다.

⚠️ **고유부 1.867 / 2.788 / 3.482는 `p50(analyze)+p50(build)`이지 "고유부의 p50"이 아니다.**
백분위의 합은 행별 합과 다르다(같은 JSON의 `stage_d_total_note`가 금지한 연산이다) — 실제로
세 패스를 그렇게 더하면 5.328 / 5.249 / 5.712인데 행별 합인 `stage_d_total_ms`는
**5.369 / 5.293 / 5.757**로 0.04ms쯤 크다. arm 간 격차(0.9~1.6ms)보다 훨씬 작아 대소 비교는
살아남지만, **이 값을 D칸에 더하거나 "고유부 비용"으로 인용하지 말 것.**

**4. 분모를 같은 세션에서 다시 쟀다.** 같은 `blit_2pass`가 08-01 02시 `gpu_sum` 3.737 →
08-03 13시 **3.675**로 −0.062ms(−1.7%) 움직였다. `gpu_sum` 노이즈 바닥 0.016ms의 **3.9배**라
조명 차이로 본다. 각 후보를 자기 세션 분모로 뺐으므로 세 값은 비교 가능하다 —
프레임타임 `baseline_diff`는 **회귀 없음**(p50 −0.11%)이라 두 세션이 같은 표에 앉을 수 있다.

⚠️ **disjoint 폐기 샘플** — `blit_2pass`(08-03) 11개 / `clahe_gamma` 6개 / `agcwd` 1개 /
`drago`(08-01) 2개. 폐기된 것이 최악 프레임일 수 있어 tail은 낙관 쪽이다.
