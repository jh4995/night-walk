# 기준 측정값 (baselines)

`outputs/`는 git이 추적하지 않는다. 그래서 **승격하지 않은 숫자는 그 머신에만 남는다** —
노트북이 바뀌거나 팀원이 확인하려 하면 근거가 없다.

여기엔 **기준이 된 측정만** 올린다. 그러면 `baseline_diff.py`가 세션·기기를 넘어서 동작한다.

## 승격 기준 (셋 중 하나면)

- `FRAME_BUDGET.md`의 칸을 채운 측정
- 팀에 숫자로 보고한 측정
- 앞으로 비교 기준으로 쓸 측정

나머지 수십 개 런은 `outputs/`에 두고 승격하지 않는다.

## 방법

```bash
cp outputs/poc_baseline/<run_ts>/summary.json docs/baselines/<날짜>_<라벨>.json
```

`summary.json`을 **그대로** 복사한다. 수 KB이고, git commit·기기 메타·판정·경고가 이미 안에 있다.
**손으로 만들거나 편집하지 않는다** — 하네스를 거치지 않은 숫자는 스탬프가 없어 비교 불가다.
복사 후 **sha256으로 원본과 바이트 동일을 확인**한다(승격은 복사이지 편집이 아니다).

명명: `<YYYYMMDD>_<조명>_<arm/무엇을_잰_것인지>_<세션id>_<기기>.json`
— 예 `20260731_poc_empty_a34.json`(초기) · `20260804_indoor_chain_bf_s5bf_a34.json`(현행).

🔴 **세션 id를 반드시 넣는다.** 같은 arm이 세션마다 승격되므로(`blit_2pass`가 지금 다섯 건)
파일명이 분모를 어느 세션에서 뺐는지 말해야 한다.
🔴 **계측이 다르면 arm 이름에 그대로 남긴다** (`_1q` = 프레임 단일 query). 접미사를 떼면
서로 뺄 수 없는 두 물리량이 같은 표에 섞인다 — ↓ "계측 방식이 조건이다" 절.

## 비교

```bash
python scripts/baseline_diff.py \
  --baseline docs/baselines/20260731_poc_empty_a34.json \
  --current  outputs/poc_baseline/<run_ts>/summary.json
```

⚠️ **조건이 다르면 비교가 아니라 착시다.** 같은 기기·같은 빌드 타입·같은 파이프라인 구성이어야
한다. `baseline_diff.py`가 `CONDITION_KEYS`로 검사해 다르면 경고를 먼저 낸다.

   차(CPU +11.8ms, NNAPI +2.6ms)는 **런 간 노이즈 + 발열 드리프트**이고, 앞선 세션들의
   `noiseA`/`noiseB`(연속 반복)와 **같은 뜻이 아니다.**
   → **그 대신** EP 격차(~60ms)가 쌍 내 차의 **5배**임이 확인되므로 **EP 결론은 발열로
   설명되지 않는다.** 교차 배치를 한 이유가 그것이다.
4. 🔴 **NNAPI arm의 `gpu_sum` p95만 7배 부푼다**(4.488 → 32.110). p50은 세 arm이 같다 —
   탐지가 ~3Hz라 **추론과 겹치는 프레임에서만** 그렇기 때문이다. 원인은 **NNAPI가 NPU가 아니라
   GPU로 내려가는 것**이고, 별도로 `/sys/kernel/gpu/gpu_busy`를 재서 확인했다
   (`detect_cpu` 2.2% vs `detect_nnapi` 43%, 최대 12% vs 97%). 기기에 `apusys_mdla0`·
   `apusys_vpu0/1`이 있는데도 안 쓴다. → **이 기기의 ③ EP는 CPU가 최선이다.**
5. ⚠️ **E가 EP에 따라 2.4배 다르다**(20.845 vs 8.730). 전처리는 **같은 코드**다 — CPU EP가
   코어를 다 먹어 전처리 스레드가 경쟁한 결과로 보인다. **E를 EP와 떼어 인용하지 말 것.**
6. ⚠️ **`duty_cycle` 95.2~96.9%는 idle-gated `상한` 조건이다.** 배포 구성이 아니다.
   그 조건에서도 표시 경로는 **29.88~29.92 FPS · `p95<80ms` 통과**했다.
7. ⚠️ **F에 letterbox 패딩이 들어 있다.** 720p(16:9)→640 정사각이라 **픽셀의 43.75%가 회색 패딩**
   (`padding_pixel_fraction`으로 기록). **다른 입력 크기의 F와 비교할 때 함께 옮길 것.**
8. ⚠️ **G는 `박스 0개` 기준이다.** 전 런 `boxes_out`=0, `max_conf` p50 0.12~0.14(임계 0.35).
   실내 장면이고 **`rotationDegrees`를 적용하지 않아 모델이 옆으로 누운 장면을 본다.**
   → **이 런들은 탐지 정확도에 대해 아무것도 말하지 않는다.** 안전 회귀는 `evaluated:false`.
9. ⚠️ **이 세션은 `run_session.py` 계획으로 몰지 않았다** — arm 전환을 손으로 했다.
   `init_run()` 스탬프·조건 대조는 `analyze_frames`가 붙였지만 **계획 지문·자동 어긋남 검사는 없다.**
10. ⚠️ **측정 APK는 `3a66ad9`**이고 후처리 순서 수정(`457ec1e`)이 들어가기 전이다.
    E·F는 그 수정과 무관하고, 박스가 0개라 G도 실질 영향이 없다.
