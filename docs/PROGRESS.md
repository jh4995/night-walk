**🔴 지금의 큰 위험 5개**
1. **지연이 빈 파이프라인에서 이미 예산 초과** — ②를 0으로 만들어도 안 줄어든다 → [FRAME_BUDGET §2](../FRAME_BUDGET.md)
2. **프로젝트 크리티컬 패스는 내 쪽이 아니다** — 상류 `C2` 자체 야간 촬영이고, 촬영 규약이 있어야 시작된다
3. **GPU 단계 비용에 상한/하한이 갈렸다** — 패스별 계측이 프레임을 중복 계상한다. 어느 쪽을 버짓표에 쓸지가 팀 결정이고, 그 사이 세 문서의 숫자가 상한으로 남는다 → [FRAME_BUDGET §3 주7](../FRAME_BUDGET.md) · [STATUS 이슈 21](STATUS.md)
4. 🆕 **④ 강조 색 지정이 명세와 충돌한다** — `person`에 **명세가 금지한 빨강**을 지정했고, 볼라드 초록과 합쳐 **적록색약 조합**이 된다. 대상이 저시력자다 → [STATUS 이슈 42](STATUS.md)
5. **탐지 임계가 근거 없는 값이었다** — 상류 export 스크립트의 기본값이 계약값처럼 굳었고, 그 임계는 **야간 볼라드를 놓친다.** 박스에 딸린 측정(G·H·I·박스 수)이 전부 그 위에 쌓여 있다 → [STATUS 이슈 38](STATUS.md)

| **3** | **폰 출력을 상류 `metrics.py` 3축으로 채점** | **골든 이미지 없이 품질을 재는 유일한 길.** 융합 채택 판단에도 쓰인다 |
| 4 | **런 안 GPU 드리프트 원인** | ⚠️ 원인 미확정. ✅ 온도 기록은 시작했다 — 이제 드리프트와 대조할 수 있다 (STATUS 이슈 23) |

하는** 일, 3은 **팀 결정을 우회하는** 시도다.

⏸ `ts`(플리커 억제)는 **§B-4 계약값 대기**라 여기 없다. `gamma_only`는 ✅ 해소됐다.

## 단계별

### 0 — 기반 ✅

문서 체계 · 계약서 · 측정 하네스(스키마 v3 · 승격 파이프라인 · 세션 오케스트레이터) ·
앱 뼈대(CameraX → GL 3패스, arm 6개) · GPU 구간 계측 · **A·B·D칸 실측**

### 1 — ② 저조도 (표시 경로)

| | 무엇 |
|---|---|
| ✅ | 단품 3종(D1·A1·A2) GPU 이식 + OpenCV 수치 대조 |
| ✅ | 단품 3종 D칸 실측 · 노이즈 바닥 |
| ✅ | **조합 2종(체인·융합) 이식 + D칸 실측** — 세션 간 분모 이동량도 확보 |
| ✅ | **`bf` 이식 + D칸 실측** — 상류 후보 `D1A1+bf`의 비용을 처음 알았다 |
| ✅ | 🔴 **계측 결함 규명** — 패스별 계측이 프레임을 중복 계상한다. 프레임 단일 query로 대조해 확정 |
| ✅ | **하한이 없던 arm 3계열 단일 query 측정** — 모든 arm에 상·하한이 생겼다 · `gamma_only` 지속 런 재측정 |
| 🟢 | **`metrics.py` 3축 채점** — 골든 이미지 없이 품질을 재는 유일한 길 |
| 🟢 | **런 안 GPU 드리프트 원인** — 온도 기록 추가가 선행 |
| ⏸ | 🆕 **D칸을 어느 계측으로 적을 것인가** ← 🔴 팀 (상한/하한/둘 다) |
| ⏸ | **융합 채택 여부** ← 🔴 팀장 (알고리즘 변경이다) |
| ⏸ | **② 최종 선택** ← 🔴 **§B-6 골든 이미지** (팀장) |
| ⏸ | `ts` / `A3` arm ← §B-4 계약값 (리셋 조건·수렴 시간) |

### 2 — ③ 위험 탐지

| | 무엇 |
|---|---|
| ✅👤 | YOLO11n `C4b` 학습 — 실야간 성능 확보 · **ONNX 수령** |
| ✅ | **ORT 추론 배관 + EP 판별** — 이 기기는 CPU가 최선(NNAPI는 GPU로 내려가 표시 경로를 침해) |
| ✅ | **E·F·G칸 실측** · **이식 정확성 대조**(폰이 PC와 같은 답을 낸다) |
| ✅ | **회전 적용** — 박스가 처음 나온다 |
| 🟢 | 🆕 **`conf` 임계 sweep 도구** — 덤프 하나로 임계 전부를 본다. ⚠️ 독립 검증 미실시 |
| ⏸ | 🆕 **`conf` 임계 확정** ← 🔴 팀 (현재 값은 상류 export 스크립트의 argparse 기본값이고 야간 볼라드를 놓친다 — 수치는 STATUS 이슈 38) |
| 🟢 | 🆕 **새 모델 `c4e_s3_11n` 배선·첫 실행** — 자체 학습 3클래스. 현행 배포판 대비 전 지표 개선 |
| ⏸ | 🆕 **비교축 확정** ← 🔴 팀. 후보가 늘었고(기각된 모델 포함, 1위 미수령, 신규 1종) **판정 기준이 안 정해졌다** |
| ⏸ | **탐지 정확도** ← 정답 라벨·골든 샘플. **"돈다"와 "맞힌다"는 다르다** |
| ⏸👤 | **`C2` 자체 야간 촬영** ← 🔴 촬영 규약·초상권 (팀원3). **상류 크리티컬 패스** |
| ⏸👤 | 보행 시점 재검증 `C5` (대시캠 한계) ← `C2` |

### 3 — ④ 선택적 강조

| | 무엇 |
|---|---|
| ✅👤 | 명세 + PC 구현 (`emphasize.py`) — 이중 스트로크·비채움·노랑/시안·빨강 금지·깜빡임 금지 |
| ✅ | **I칸 — 실물 오버레이 GL 이식·측정 완료.** 최초 범위 B·D·I가 다 찼다 |
| ✅ | 🏆 **③→④ 연결.** 🔴 색을 **번호가 아니라 이름으로** 고른다 — 계약서와 모델이 정반대라 번호로 걸면 사람과 계단의 색이 뒤바뀐다. 이름으로 걸면 **팀이 어느 쪽으로 정하든 코드가 안 바뀐다** |
| ✅ | **H칸 — 박스 좌표 평활·hold** 들어감. 🔴 **안전 항목이다**(3.4Hz라 박스가 튄다) |
| ✅ | **깜빡임 검출기** — 안전 항목을 눈이 아니라 지표로 잡는다 |
| ⏸ | 🔴 **`bollard` 색 + `person` 색 재확인** ← 팀장. 지시(초록·빨강)가 명세(빨강 금지·시안)와 충돌한다 (STATUS 이슈 42) |
| ⏸ | 🆕 **스펙의 "경계선 밖 불변"이 `cv2.rectangle` 동작과 모순** ← 팀장 (`thickness`·좌표 규약 질의) |
| ⏸ | **통합 후 I칸·H칸 재측정** ← 박스 개수가 장면마다 다르다. 야간에서 잰다 |

| ⏸ | C칸 실측 ← 위 결정 (흡수되면 C칸 자체가 없어진다) |

| | 무엇 |
|---|---|
| ✅ | **표시/탐지 경로 분리 구현** — 탐지는 카메라 원본을, ②는 표시용만. ⏸ **추인만 대기** |
| ✅ | 🏆 **파이프라인이 닫혔다** — 카메라 → ② → 화면, 카메라 → ③ → ④ → 화면 |

| ⏸ | 탐지 주기 N 확정 ← 🔴 팀 (안전 판단이다) |

| | 무엇 |
|---|---|
