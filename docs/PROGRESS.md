**🔴 지금의 큰 위험 3개**
1. **지연이 빈 파이프라인에서 이미 예산 초과** — ②를 0으로 만들어도 안 줄어든다 → [FRAME_BUDGET §2](../FRAME_BUDGET.md)
2. **프로젝트 크리티컬 패스는 내 쪽이 아니다** — 상류 `C2` 자체 야간 촬영이고, 촬영 규약이 있어야 시작된다
3. 🆕 **GPU 단계 비용에 상한/하한이 갈렸다** — 패스별 계측이 프레임을 중복 계상한다. 어느 쪽을 버짓표에 쓸지가 팀 결정이고, 그 사이 세 문서의 숫자가 상한으로 남는다 → [FRAME_BUDGET §3 주7](../FRAME_BUDGET.md) · [STATUS 이슈 21](STATUS.md)

## 🟢 지금 당장 가능 — 7개

| 우선 | 무엇 | 값 |
|---|---|---|
| **1** | **하한이 없는 arm 3계열의 단일 query 측정** | 🔴 `fused`·`fused_bf`·`highlight` 계열엔 **상한만 있다.** 부풀림 %를 옮겨 보정할 수 없다 (STATUS 이슈 22) |
| **2** | **폰 출력을 상류 `metrics.py` 3축으로 채점** | **골든 이미지 없이 품질을 재는 유일한 길.** 융합 채택 판단에도 쓰인다 |
| **3** | **런 안 GPU 드리프트 원인** | ⚠️ +13% 관측했는데 **온도를 안 재서 원인 미확정.** 온도 기록 추가가 선행 (STATUS 이슈 23) |
| 4 | ③ 추론 배관 (더미 모델) | `C10`이 팀장·팀원2 공동. 모델 도착 시 대기 0 |
| 5 | `ts`(플리커 억제) 이식·측정 | 후보 `D1A1+bf+ts`의 **마지막 조각.** ⏸ **§B-4(리셋 조건·수렴 시간)가 ☐**라 지어내지 말 것. 수렴 구간을 warmup에서 어떻게 다룰지도 함께 정해야 한다 |
| 6 | `gamma_only` 지속 런 재측정 | 작은 빚 (STATUS 이슈 7) |

**1·2·3의 성격이 다르다** — 1은 **이미 낸 숫자의 반쪽을 채우는** 측정, 2는 **막힌 것을 우회하는** 시도,
3은 **측정 신뢰도 자체를 지키는** 일이다.

## 단계별

### 0 — 기반 ✅

문서 체계 · 계약서 · 측정 하네스(스키마 v3 · 승격 파이프라인 · 세션 오케스트레이터) ·
앱 뼈대(CameraX → GL 3패스, arm 6개) · GPU 구간 계측 · **A·B·D칸 실측**

### 1 — ② 저조도 (표시 경로)

| | 무엇 |
|---|---|
| ✅ | 단품 3종(D1·A1·A2) GPU 이식 + OpenCV 수치 대조 |
| ✅ | 단품 3종 D칸 실측 · 노이즈 바닥 |
| ✅ | **조합 2종(체인·융합) 이식 + D칸 실측** — 세션 간 분모 이동량도 확보 |
| ✅ | **`bf` 이식 + D칸 실측** — 상류 후보 `D1A1+bf`의 비용을 처음 알았다 |
| ✅ | 🔴 **계측 결함 규명** — 패스별 계측이 프레임을 중복 계상한다. 프레임 단일 query로 대조해 확정 |
| 🟢 | **하한이 없는 arm 3계열 단일 query 측정** · **`metrics.py` 3축 채점** · `gamma_only` 재측정 |
| 🟢 | **런 안 GPU 드리프트 원인** — 온도 기록 추가가 선행 |
| ⏸ | 🆕 **D칸을 어느 계측으로 적을 것인가** ← 🔴 팀 (상한/하한/둘 다) |
| ⏸ | **융합 채택 여부** ← 🔴 팀장 (알고리즘 변경이다) |
| ⏸ | **② 최종 선택** ← 🔴 **§B-6 골든 이미지** (팀장) |
| ⏸ | `ts` / `A3` arm ← §B-4 계약값 (리셋 조건·수렴 시간) |

### 2 — ③ 위험 탐지

| | 무엇 |
|---|---|
| ✅👤 | YOLO11n `C4b` 학습 — 실야간 성능 확보 |
| 🟢 | **추론 배관 (더미/사전학습 모델)** — ORT 경로 뚫기 |
| ⏸👤 | **`C2` 자체 야간 촬영** ← 🔴 촬영 규약·초상권 (팀원3). **상류 크리티컬 패스** |
| ⏸👤 | 보행 시점 재검증 `C5` (대시캠 한계) ← `C2` |
| ⏸ | ONNX export · 실모델 이식 ← **해상도 · opset · NMS** (팀원1) |
| ⏸ | **E·F·G칸 실측** ← 모델 수령 |

### 3 — ④ 선택적 강조

| | 무엇 |
|---|---|
| ✅👤 | 명세 + PC 구현 (`emphasize.py`) — 이중 스트로크·비채움·노랑/시안·빨강 금지·깜빡임 금지 |
| ✅ | **I칸 — 실물 오버레이 GL 이식·측정 완료.** 최초 범위 B·D·I가 다 찼다 |
| ⏸ | 🆕 **스펙의 "경계선 밖 불변"이 `cv2.rectangle` 동작과 모순** ← 팀장 (`thickness`·좌표 규약 질의) |
| ⏸ | **H칸 — 박스 좌표 평활·hold** ← 탐지 연동. 🔴 **안전 항목이다**(깜빡임) |

### 4 — ① 눈부심

| | 무엇 |
|---|---|
| ⏸ | **별도 단계로 둘 것인가** — `D1A1+bf` 채택 시 **②에 흡수** ← 팀 추인 |
| ⏸ | C칸 실측 ← 위 결정 (흡수되면 C칸 자체가 없어진다) |

### 5 — 통합·구조

| | 무엇 |
|---|---|
| ⏸ | **표시/탐지 경로 분리 구현** ← 🔴 팀 추인 |
| 🟡 | **분리가 실제로 병렬인지 실측** — 같은 GPU를 나눠 쓰면 공짜가 아니다 |
| 🟡 | 🔴 **지연 원인 조사** — 최대 위험. 범위를 팀에 물어놨다 (진단 분해만이라도 착수 가능) |
| ⏸ | J칸 (`Choreographer`/`FrameMetrics`) — 로그 스키마에 열이 없다 |
| ⏸ | 탐지 주기 N 확정 ← 실측 |

### 6 — 검증·시연

| | 무엇 |
|---|---|
| ✅ | 지속 FPS · 지연 (빈 파이프라인 + ② arm + `bf` + ④) — **상류 `C11`을 절반 해뒀다** |
| 🟡 | **발열은 재해석됐다** — "드리프트 없음"은 가벼운 arm 한정이고, 무거운 arm에서 런 안 +13%를 봤다. **온도를 안 재서 원인 미확정** |
| ⏸ | 🔴 **안전 회귀**(위험물 강조 누락률) ← ③ 탐지 필수. 지금 모든 보고가 `evaluated:false` |
| ⏸ | 전체 파이프라인 지속 FPS ← 통합 |
| ⏸👤 | 골판지 하우징 발열 · 현장 라이브 데모 ← 폼팩터 |
