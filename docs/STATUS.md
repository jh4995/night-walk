## 하네스 검증 이력 (왜 3라운드나 돌았나)

| 회차 | 결과 |
|---|---|
| 1차 검증 | **FAIL 2** — ① 경계 밖 프레임 간격이 경고 없이 폐기돼 12초 스톨이 `max=33ms, PASS`로 보고 ② `baseline_diff`가 데이터 없음을 "회귀 없음 + exit 0"으로 처리 |
| 2차 검증 | 위 2건 수정 확인 + 새 표면 8개 PASS. **새 FAIL 2** — 행이 카운트 없이 사라지는데 `data_complete:true`가 손실을 **부정** |
| 3라운드 수정 | 행 소실을 사유별 계수(`warmup`은 의도된 제외로 분리), **회계 불변식** 도입, 시계 혼용 교차검사 2종 추가 |

넷 다 **"데이터가 조용히 사라진다"는 같은 계열**이었다. 회계 불변식
(`rows_read != rows_used + 소실합` → 예외)이 그 계열을 구조적으로 막는다.

> **교훈:** 처음엔 내가 만들고 내가 검증했고, 그때는 이 4건을 하나도 못 잡았다.
> 자체 검증은 "실패해야 할 입력이 실패하는가"만 봤고, **"성공 경로가 조용히 데이터를 잃는가"**
> 는 보지 않았다. 만든 사람은 자기 가드를 의심할 이유를 못 찾는다.
